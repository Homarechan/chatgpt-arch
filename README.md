# chatgpt-arch

Arch Linux用のChatGPT非公式PKGBUILDです。

このリポジトリは、OpenAIが配布している公式Debianパッケージ
`chatgpt_amd64.deb` の中身を再ビルドせず、Arch Linux向けに再パッケージするためのものです。

## これは何か

`PKGBUILD`は、公式debを入力として扱い、deb内の`data.tar.xz`をArchパッケージの`$pkgdir`へ展開します。
アプリ本体のバイナリや同梱ライブラリは再コンパイルしません。

含まれる主な処理は次の通りです。

- `/usr/lib/chatgpt`以下のElectron/Chromium系アプリ本体をそのまま配置
- `/usr/bin/chatgpt`の起動用シンボリックリンクをdebと同じ形で維持
- `/usr/share/applications/chatgpt.desktop`を配置
- `/usr/share/pixmaps/chatgpt.png`を配置
- `/etc/apparmor.d/chatgpt`を設定ファイルとして扱う
- Debian固有の`/usr/share/lintian`は除外
- deb内のcopyrightをArchの`/usr/share/licenses/chatgpt-bin/copyright`にも配置

## Codexによる生成について

このPKGBUILDとinstall scriptはCodexが生成しました。

作業では、まず公式debをローカルで調査しました。`dpkg-deb`が利用できない環境だったため、debをDebian形式の`ar`アーカイブとして展開し、`control.tar.xz`と`data.tar.xz`を直接確認しました。

Codexが確認した主な項目は次の通りです。

- debの`control`情報
- Debian依存関係
- `postinst`、`postrm`、`prerm`
- `conffiles`
- `/usr`以下のファイル配置
- `.desktop`ファイル
- アイコンファイル
- 同梱共有ライブラリ
- 実行ファイルの外部SONAME依存

Debianの`postinst`にはAPTリポジトリ登録処理が含まれていましたが、Arch Linuxのパッケージとしては不要なため移植していません。
一方で、desktop database更新とAppArmor profileの扱いはArch向けの`chatgpt-bin.install`へ必要最小限で移植しています。

依存関係はdebの`Depends`を起点に確認し、Arch Linux上の対応パッケージへ写像しました。
また、debのcontrolには明示されていないものの、同梱されている`libqt5_shim.so`と`libqt6_shim.so`がQtライブラリを直接必要としていたため、`qt5-base`と`qt6-base`も依存関係に含めています。

## GitHubへの公開について

このリポジトリへの初回commitとGitHubへのpushもCodexが実行しました。

公開前に、Codexは公開対象を次の3ファイルだけに絞りました。

- `.gitignore`
- `PKGBUILD`
- `chatgpt-bin.install`

deb本体、生成済みのArchパッケージ、deb展開済みの`control`/`data`、作業用ディレクトリはcommitしていません。
特に、debのメンテナスクリプト内に含まれていたAPTリポジトリ関連の鍵データは、READMEやcommit対象ファイルへ持ち込まないようにしました。

commit前には、キー、トークン、パスワード、ローカルユーザー名、ローカルパスなどが含まれていないかを検索し、問題のないファイルだけをstageしました。
commit authorもローカルメールアドレスではなく、GitHubのnoreply形式に設定してからcommitしました。

## ビルド方法

同じディレクトリに公式debを`chatgpt_amd64.deb`という名前で置いてから、次を実行します。

```bash
makepkg -si
```

`makepkg -si`はインストール時に`sudo`パスワードを要求します。
Codexによる検証では、パッケージ生成の`makepkg -f`は成功しました。
実インストールはユーザー側で行う前提です。

## 注意

これは公式Arch Linuxパッケージではありません。
公式debの中身をArch Linux向けに再パッケージするための非公式PKGBUILDです。

公式debのバージョンが変わった場合は、`pkgver`、`sha256sums`、依存関係、install scriptの内容を再確認してください。

# chatgpt-arch

An unofficial Arch Linux PKGBUILD for ChatGPT.

This repository repackages the official Debian package distributed by OpenAI,
`chatgpt_amd64.deb`, for Arch Linux without rebuilding the application binaries.

## What This Is

The `PKGBUILD` treats the official deb as the input artifact and extracts the
deb's `data.tar.xz` into Arch's `$pkgdir`. The application binary and bundled
libraries are not recompiled.

The package preserves the important layout from the deb:

- the Electron/Chromium-based application under `/usr/lib/chatgpt`
- the `/usr/bin/chatgpt` launcher symlink
- `/usr/share/applications/chatgpt.desktop`
- `/usr/share/pixmaps/chatgpt.png`
- `/etc/apparmor.d/chatgpt`, tracked as a configuration file
- the deb copyright file, also installed under `/usr/share/licenses/chatgpt-bin/copyright`

Debian-specific lintian metadata under `/usr/share/lintian` is omitted because
it is not useful in an Arch package.

## Generated by Codex

This PKGBUILD and install script were generated by Codex.

Codex inspected the official deb locally. Because `dpkg-deb` was not available
in the working environment, Codex treated the deb as a Debian-format `ar`
archive and directly extracted `control.tar.xz` and `data.tar.xz`.

Codex checked the following package details before writing the Arch packaging:

- the deb `control` metadata
- Debian dependency declarations
- `postinst`, `postrm`, and `prerm`
- `conffiles`
- the file layout under `/usr`
- the `.desktop` file
- the icon file
- bundled shared libraries
- external SONAME dependencies of executable files

The Debian `postinst` script contains APT repository registration logic. That
logic is Debian-specific and was intentionally not ported to Arch Linux. The
only maintainer-script behavior carried over was the minimal Arch-relevant
handling for desktop database updates and the included AppArmor profile.

Dependencies were mapped from the deb's `Depends` field to Arch package names.
Codex also checked the bundled ELF files. `qt5-base` and `qt6-base` are included
because the bundled `libqt5_shim.so` and `libqt6_shim.so` directly require Qt
libraries, even though those dependencies were not explicitly listed in the deb
control metadata.

## GitHub Publishing

Codex also performed the initial Git commit and pushed the repository to GitHub.

Before publishing, Codex limited the first commit to only these files:

- `.gitignore`
- `PKGBUILD`
- `chatgpt-bin.install`

The deb file itself, generated Arch package archives, extracted deb
`control`/`data` contents, and temporary working directories were not committed.
Codex also avoided copying APT repository key material found in the Debian
maintainer scripts into this repository.

Before committing, Codex searched the files intended for publication for keys,
tokens, passwords, local usernames, and local filesystem paths. Only the safe
packaging files were staged. The commit author was configured to use a GitHub
noreply address instead of a local email address.

## Building

Place the official deb in the repository root as `chatgpt_amd64.deb`, then run:

```bash
makepkg -si
```

`makepkg -si` will require sudo authorization when installing the package. Codex
verified that package creation with `makepkg -f` succeeded. The actual system
installation is expected to be performed by the user.

## Notes

This is not an official Arch Linux package. It is an unofficial PKGBUILD for
repackaging the official deb for Arch Linux.

When the official deb version changes, review `pkgver`, `sha256sums`,
dependencies, and the install script again.
